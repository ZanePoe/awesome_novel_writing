# 2026-11-25 合集多语言化

按 `awesome_ai_video_creation` 已合入的框架移植：英语为默认（仓库根 `README.md`、`docs/`、`CONTRIBUTING.md`），中文/西班牙语/印地语/法语镜像在 `locales/<lang>/`；42 个项目、5 种语言、16 个生成文件。

## 本仓库的特有设计

- `locales/<lang>/entries.json` 除 `description`、`boundary`、`license_label`、`license_note` 外还必须给 `form`（形态，中文原文如「桌面应用」「Skill 包」）；`zh` 回落 `data/projects.json`，因此没有 `locales/zh/entries.json`。
- 7 个规范名含 CJK 的仓库在 en/es/hi/fr 各给无 CJK 的 `name`：`EthanYoQ/Pagekin`→`Pagekin`（官方 README 标题即 Pagekin）、`yilujian/easy-writing`→`easy-writing`（官方英文标题 `Easy Writing（易创）`）、`yuanbw2025/storyforge`→`StoryForge`、`xiaoshengxianjun/51mazi`→`51mazi`、`FlickeringLamp/ai-novelist`→`ai-novelist`（README_EN 自述品牌 QingZhu 只在正文说明，展示名保留仓库原名）、`usagifufu/FuFu-Novel-Writing`→`FuFu`、`looplj/reveric`→`Reveric`。
- 语言切换行、页内锚点、`<a id>`、CSV 的 `maintenance_tier`（0–3）与 `check_links()` 口径同 pilot；`docs/research.md` 是允许保留字面中文关键词的唯一例外。

## 移植时修掉的框架缺陷

1. `anchor()` 用 `str.isalnum()` 判定保留字符，天城文组合符（matra）会被误删；现与 GitHub 实测对齐（见「分类标签导航」一节）。
2. `validate()` 与 `tests/test_i18n.py` 各写一套「无汉字」正则（只用 Han 区间，漏 `、`、`「」`、全角括号）；统一为 `build.CJK`。
3. `check_links()` 的生成物豁免按 href 字面匹配，平级写法（`projects.md`）会误判；改为比较解析后的绝对路径与该 locale 的生成物集合。
4. `render_all` 在 Windows 上混用 `str(Path)` 与 `.as_posix()` 键名，镜像 README 必 `KeyError`；统一 `as_posix()`。

## README 开头的分类标签导航

每份 README 在 intro 之后、「当前收录」之前新增 `## 分类导航`（en `Jump to a category`、es `Ir a una categoría`、hi `श्रेणी पर जाएँ`、fr `Aller à une catégorie`），按 `ui.json.categories` 顺序一行列出 6 个分类的页内链接，可点击跳到对应 `### 分类` 小节。`anchor()` 按 GitHub 渲染页实测校准（抓取每个 `### 分类` 自带锚点逐一比对）：GitHub 的 README 标题 id 删除 `、`、`.` 等标点，保留中日韩文字、带重音拉丁字母与天城文组合符，空格转 `-`；实现即「保留字母/数字/Unicode 组合符（Mn/Mc/Me）/`_`/`-`，其余删除」。中途曾按 npm 包 `github-slugger` 的字符集改成保留 `、`，实测「文风修订、去模板化与质量检查」等锚点跳不动，已回退。`test_tag_navigation_covers_every_category` 断言导航与 `### ` 小节一一对应。
